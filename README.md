# БЛИЦ — Streamer Quiz

Версия с простой авторизацией без Twitch.

## Как работает авторизация

1. Пользователь нажимает «Авторизация».
2. Сервер сразу создаёт новую учётную запись.
3. Пользователю выдаётся случайный ID от 0 до 100000.
4. ID хранится на сервере, повторно занять уже используемый ID нельзя.
5. Сессия сохраняется в защищённой HttpOnly cookie.

## Админка

В проекте нет публичной кнопки админки. Владелец открывает секретный маршрут:

`/manage/<ADMIN_PANEL_KEY>`

Задай в Render переменную окружения:

`ADMIN_PANEL_KEY` = длинная случайная строка.

Также рекомендуется задать `SESSION_SECRET` длинной случайной строкой.

После открытия секретной ссылки сервер выдаёт мастер-cookie владельца и открывает `/admin.html`. Админские API дополнительно требуют учётную запись с `admin: true`.

В админке можно:
- смотреть всех пользователей и их ID;
- видеть количество прохождений и правильных ответов;
- редактировать стримеров, вопросы и ответы;
- выдавать права администратора по ID;
- забирать права администратора по ID.

Обычным пользователям ссылка на админку не показывается.

## Render

Build Command: `npm install`
Start Command: `npm start`

Переменные:
- `ADMIN_PANEL_KEY`
- `SESSION_SECRET`
- `NODE_ENV=production`


Админ-панель: `/admin-panel-OPROS.html`. Обычная кнопка сайта не показывает эту ссылку.
Авторизация создаёт аккаунт только один раз: сессионная cookie хранится 1 год, поэтому F5 не меняет ID и не выходит из аккаунта. Если пользователь уже авторизован, повторное нажатие «Авторизация» возвращает тот же аккаунт.

### Финальный трек и фотографии
Для каждого стримера в редакторе админки есть отдельный блок финала:
- прямая ссылка на аудиофайл MP3/OGG/WAV/M4A;
- время начала трека в секундах;
- время окончания (0 = до конца);
- включение/выключение трека;
- галерея из 10–20 прямых ссылок на изображения.
После завершения теста выбранный трек запускается на заданном отрезке, а фотографии автоматически сменяют друг друга в финальной карточке результата.

### Медиа в финале
В админке музыка и фотографии теперь загружаются файлами, без вставки URL.
- Музыка: один аудиофайл, можно выбрать начало и конец воспроизведения.
- Фото: можно загрузить сразу несколько файлов, от 10 до 20.
- На странице результата фотографии не листаются альбомом — они по очереди падают сверху на экран.
- Загруженные файлы сохраняются в папке `uploads/`.

Для Render учти: локальная файловая система сервиса не является постоянным хранилищем при redeploy/restart. Для постоянного хранения загруженных фото и музыки позже лучше подключить Cloudinary, S3 или другое объектное хранилище.


## Постоянное хранение на Render

В этой версии данные вынесены из обычной файловой системы сервиса на Persistent Disk Render.

**Что сохраняется:**
- вопросы, ответы и правильные варианты;
- настройки и видимость стримеров;
- пользователи, ID, статистика, баны и админские права;
- загруженные фотографии;
- загруженная музыка;
- сессии пользователей.

### Настройка Render
1. Открой Web Service проекта.
2. Добавь **Persistent Disk**.
3. Mount Path поставь строго: `/var/data`.
4. После этого сделай redeploy.

Сервер автоматически использует `/var/data`, когда запущен на Render, и создаёт там `data.json` и папку `uploads/`. Уже сохранённые данные на диске не перезаписываются при redeploy.

**Важно:** Persistent Disk нужен именно для постоянного хранения файлов. Без него Render может удалить локальные загруженные файлы и изменённый `data.json` после перезапуска/redeploy.


### Render Free
Эта версия не требует Persistent Disk. Если /var/data недоступен, сервер автоматически использует writable `persistent-data`. Кнопка резервной копии доступна в админ-панели через `/api/admin/backup`.
